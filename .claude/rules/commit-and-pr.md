# 커밋·PR 시점 (세션 역할별)

작성자(사용자)가 PR을 직접 머지한다. 어느 세션도 머지하지 않는다.

## 개발 세션

- 작업과 검증이 끝나면 **묻지 않고** 커밋 → push → `gh pr create`까지 한다.
- PR을 연 뒤 생긴 수정은 같은 브랜치에 커밋을 더한다.
- 새 의존성·전역 도구 설치, 외부 서비스로 내보내는 작업은 여전히 먼저 묻는다.

## 디자인·기획 세션

**다른 세션에 문서를 넘기는 시점마다** 묻지 않고 커밋 → push → PR을 연다. Phase가 끝날 때까지 모아 두지 않는다.

| 세션 | 커밋·PR 시점 |
| --- | --- |
| 디자인 | 개발·기획에 답변·인계·검토 문서(`NN-주제.md`)를 쓴 때, `DESIGN.md` 반영안을 넘길 때 |
| 기획 | PRD 상태가 바뀐 때(`approved` 등), 디자인·개발에 요청·답변을 보낸 때 |
| 공통 | Phase가 끝나 `archive/`로 정리할 때 |

- PR 본문 첫 줄에 **무엇을 누구에게 넘기는지**를 쓴다(예: "디자인 36번: 개발에 PR-19~21 검토 결과를 넘긴다"). 작성자는 이 줄을 보고 머지한다.
- 자기 폴더(`cowork/design/` 또는 `cowork/prd/`)의 파일만 커밋한다.
- 개발 세션이 같은 작업 폴더를 쓰는 중이면 브랜치를 바꾸지 않고 `origin/main` 기준 별도 `git worktree`에서 PR을 만든다.

## 공통

- 커밋할 파일은 이름을 지정해 `git add`한다. 자세한 규칙은 [git-shell.md](./git-shell.md).
- 저장소가 public이므로 비밀·연락처·내부 수치는 커밋하지 않는다.
