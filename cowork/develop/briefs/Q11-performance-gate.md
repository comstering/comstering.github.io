# Q11 기획 확인 요청: 성능 게이트(G1-1·G1-2)를 어떤 측정으로 정할까

작성: 개발 세션 · 2026-10-29
대상: 기획 세션 (결정), 디자인 세션 (참고)
관련: [`REQUESTS.md`](../REQUESTS.md) Q9·Q11, [`design/19`](../../design/19-design-answer-q9-font-a11y.md) 3장, PRD-003 G1-1·G1-2, PRD-001 5.2 NF 표
상태: **기획 결정 대기.** 결정 전까지 CI는 성능·LCP·CLS를 경고(`warn`)로만 둔다.

## 1. 한 줄 요약

> 같은 사이트가 **Lighthouse "시뮬레이션" 측정으로는 LCP 3.8~4.5s·성능 76~83점(목표 미달)**, **실제 Chrome에서 네트워크를 제한해 관측하면 LCP 1.8~1.9s·성능 98점(목표 달성)**이다. 게이트를 어느 측정으로 정할지가 먼저고, 숫자는 그다음이다.

## 2. 현재 게이트 문구와 문제

| 문서 | 문구 |
| --- | --- |
| PRD-003 G1-1 | 글 상세 LCP ≤ 2.0s, CLS ≤ 0.05 (모바일, 이미지가 가장 많은 글 기준), Lighthouse CI |
| PRD-003 G1-2 | 홈·글 상세·About Lighthouse 성능 ≥ 95, 접근성 100 |
| PRD-001 5.2 | LCP ≤ 2.0s **(모바일 4G)**, 도구 "Lighthouse, CrUX". 모범사례 ≥ 95 |

문구가 "어떤 조건의 Lighthouse인지" 정하지 않아서, CI가 쓰는 기본 측정(시뮬레이션)으로 재면 PR-14(이미지 최적화)까지 끝내도 통과하지 못한다.

## 3. 측정 결과 (모두 개발이 직접 측정, 3회 중앙값, 모바일 프리셋)

| 측정 방식 | 홈 | 글 상세 | About |
| --- | --- | --- | --- |
| **A. CI 시뮬레이션**(현재 CI, 리눅스, PR #43) 성능 · LCP | 83 · 3.8s | 76 · 4.5s | 76 · 4.1s |
| B. 로컬 시뮬레이션(맥) 성능 · LCP | 83 · 3.9s | 77 · 4.5s | 68 · 6.9s |
| **C. 관측**(`throttlingMethod: devtools`, 실제 Chrome에 4G급 제한) 성능 · LCP | **98 · 1.84s** | **98 · 1.90s** | **98 · 1.92s** |
| D. 하한: CSS·JS·글꼴이 없는 최소 페이지(시뮬레이션) | LCP 0.75s, 성능 100 | | |

- A·B의 "시뮬레이션"은 Lighthouse 기본값이다. 실제로 느린 망을 만들지 않고 한 번 잰 결과로 모델링해 계산한다.
- C는 실제 Chrome이 제한된 망·CPU에서 로딩한 시간을 그대로 관측한다.
- D가 말하는 것: 이 측정 환경에서 LCP 2.0s는 불가능한 숫자가 아니다.

### 개발 쪽 실험 (시뮬레이션 기준, 커밋하지 않은 일회성 실험)

| 실험 | 홈 LCP | 글 LCP | About LCP | 해석 |
| --- | --- | --- | --- | --- |
| 기준(현재 main) | 3.9s | 4.5s | 6.9s | |
| CSS를 HTML에 인라인(`experimental.inlineCss`) | 3.6s | 4.2s | 6.5s | 약 0.3s 개선. 렌더링 차단 CSS 요청 1회 제거 효과 |
| Pretendard 글꼴·CSS 제거(시스템 글꼴) | **2.2s (성능 99)** | **2.5s (98)** | 4.1s (87) | CSS가 107KB → 61KB, 글꼴 요청 12~17개 제거 |
| 글꼴을 2MB짜리 1개로 교체 | 12.3s | 12.5s | 13.3s | **글꼴 바이트가 시뮬레이션 LCP에 그대로 더해진다** |

- About이 다른 페이지보다 느린 이유는 확인하지 못했다. 추정: `profile.png`(364KB, `public/` 루트라 이미지 변환 대상이 아님)와 글 목록보다 긴 본문. 글꼴을 빼도 About만 4.1s로 남는다.
- 두 번째 행과 네 번째 행의 비교로, **시뮬레이션은 웹 글꼴 크기를 LCP에 얹는다**는 것을 확인했다. 실제 브라우저(C)는 글꼴이 늦어도 `font-display: swap`이라 글자를 폴백 글꼴로 먼저 그려서 LCP가 2s 안이다.

### 디자인 19번과의 관계

디자인 19번은 "글꼴 방식은 LCP 레버가 아니다"라고 측정했다(자체 에뮬레이션 1.6Mbps·RTT 150ms·CPU 4배, FCP=LCP 2.65~3.40s로 모든 방식 동일). 개발의 Lighthouse 시뮬레이션은 글꼴이 크게 반영된다. **두 측정은 서로 다른 방식이라 결과가 갈리는 것이지 어느 한쪽이 틀린 게 아니다.** 어느 쪽이 "독자가 겪는 시간"에 가까운지가 아래 결정의 핵심이다. C(관측)가 디자인 19번의 에뮬레이션과 같은 계열이고 값도 비슷하다(1.9s대).

## 4. 숫자 외에 걸린 것

| 항목 | 현재 | 원인·판단 |
| --- | --- | --- |
| 모범사례 ≥ 95 (PRD-001) | **82** | 실패 감사가 **`is-on-https` 하나**(로컬 `http://localhost`에서 재서). 실서비스는 HTTPS(GitHub Pages)라 실제 문제가 아니다. 이 감사는 로컬·CI 측정에서 항상 걸린다 |

| 접근성 100 | 통과 | 이미 CI `error` |
| SEO 100 | 통과 | 이미 CI `error` |

## 5. 선택지

| | 내용 | 개발 비용 | 위험 |
| --- | --- | --- | --- |
| **O1. 문구 유지** | 시뮬레이션 LCP ≤ 2.0s·성능 ≥ 95를 그대로 두고 개발이 줄인다 | 큼. 글꼴을 사실상 빼거나 시스템 글꼴을 먼저 쓰는 방향이 필요(위 실험상 글꼴 제거 시 홈 2.2s). 단일 서브셋(102KB) + CSS 인라인 조합의 효과는 **미측정**(선형 추정으로 홈 약 2.5~2.7s) | **디자인 영향이 크다**(Pretendard 기준으로 맞춘 줄 길이·자간). 달성도 불확실 |
| **O2. 관측 측정으로 문구 변경** (개발 추천) | "모바일 4G 제한을 건 실제 Chrome 관측(`throttlingMethod: devtools`), 3회 중앙값"으로 정의. 현재 이미 통과(1.8~1.9s, 98점) | 작음. `lighthouserc.json` 설정 한 줄 + PR 댓글 문구 | CI 러너 성능에 따라 값이 흔들릴 수 있다(미측정). 3회 중앙값과 여유(예: LCP ≤ 2.0s에 현재 1.9s는 여유가 작다)가 필요 |
| **O3. 시뮬레이션 기준 완화** | 시뮬레이션 유지, 숫자만 완화(예: LCP ≤ 4.0s, 성능 ≥ 80) | 거의 없음 | 숫자 근거가 약하고 Google Core Web Vitals "good"(실사용 75퍼센타일 LCP 2.5s)과도 다른 척도라 의미가 흐리다 |
| **O4. 실사용 데이터** | 배포 후 PageSpeed Insights/CrUX로 LCP 확인(게이트는 보조) | PR 게이트로는 못 씀 | 트래픽이 적으면 CrUX 데이터가 없다 |

### 개발 추천: O2 (+ 모범사례는 `is-on-https` 제외)

- 근거: 독자가 겪는 시간에 가장 가까운 측정이 C이고, 이미 목표를 달성한다. O1은 디자인을 바꿔야 하는데 얻는 것은 "시뮬레이션 점수"다.
- 글꼴 서브셋(design/19 ①)은 성능 게이트와 **분리**해서 진행한다. 목적은 요청 수·전송량 감소와 CLS 확인이다.
- 모범사례: 측정 대상이 `http://localhost`라 `is-on-https`를 게이트에서 빼거나(`skipAudits`), 모범사례 기준을 "HTTPS 제외"로 쓴다.
- 확인하지 못한 것: C 방식이 **리눅스 CI에서도 안정적인지**(이번 측정은 로컬 맥). 결정 후 PR로 올려 CI 3회 중앙값을 확인하고 값이 흔들리면 여유 폭을 다시 정한다.

## 8. 측정 조건과 재현

- 환경: 맥(arm64) Chromium, `yarn build` 산출물을 Lighthouse CI `staticDistDir`로 서빙, `http://localhost`, 모바일 프리셋(Lighthouse 기본), 페이지마다 3회 중앙값, 2026-10-29, 커밋 `8f0ca5a`(main).
- CI 행(A)은 리눅스 GitHub Actions의 PR #43 Lighthouse 댓글 값이다.
- 재현: `yarn build && yarn lhci`(시뮬레이션). 관측 측정은 `lighthouserc.json`의 `collect.settings`에 `{"throttlingMethod":"devtools"}`를 넣어 실행한다. 실험(인라인 CSS·글꼴 제거·2MB 글꼴)은 설정을 임시로 바꿔 측정했고 저장소에는 반영하지 않았다.
- **한계:** 실제 Chrome(Claude in Chrome)·Safari·실기기·실서비스(HTTPS) 측정은 하지 않았다. CI에서의 관측 측정 안정성은 미확인.
