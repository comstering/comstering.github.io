# cowork/develop

개발 담당(Claude Code)의 작업 공간. **기획자·디자이너가 "지금 어디까지 구현됐고, 다음은 무엇이고, 무엇을 고쳐야 하는지"를 한곳에서 보게 하는 곳**이다.

## 문서

| 파일 | 내용 | 갱신 시점 |
| --- | --- | --- |
| [CONTEXT.md](./CONTEXT.md) | **새 세션이 먼저 읽는 인수인계 문서.** 역할, 확정 결정, 읽는 순서, PR 작업 흐름, 명령, 스크린샷 방법, 함정 | 규칙이 바뀔 때 |
| [STATUS.md](./STATUS.md) | PR별 진행 상태, 시안 대비 구현 차이, 기획·디자인에 묻는 것, 측정값 | PR을 열거나 머지할 때마다 |
| [REQUESTS.md](./REQUESTS.md) | 개발 → 기획·디자인 질문과 요청 (번호 `Q1`~). 답이 오면 답을 적고 닫는다 | 질문이 생기거나 답이 올 때 |

## 규칙

- 개발은 PRD 번호·PR 번호·기능 ID(F-PO-03 등)·디자인 문서 번호(12번 E1 등)를 그대로 인용한다.
- 시안과 다르게 구현한 곳은 숨기지 않고 STATUS.md의 "시안 대비 차이"에 적는다. 디자이너는 거기서 수정 여부를 정한다.
- 기획·디자인의 답은 `cowork/prd`, `cowork/design`에 적고, 여기에는 REQUESTS.md의 답변란에 번호만 링크한다.
- 합의 전 내용은 구현 기준이 아니다(`cowork/design/README.md`와 같은 규칙).

## 폴더

| 경로 | 내용 |
| --- | --- |
| `briefs/` | 기획·디자인과 맞춰야 할 질문을 근거(측정·선택지·결정 요청)와 함께 정리한 문서. 번호는 REQUESTS.md 질문 번호(`Q11-….md`) |
| `tools/shoot.mjs` | PC·Mobile 스크린샷 촬영 (정적 빌드 기준) |
| `tools/publish-shots.sh` | 스크린샷을 `pr-screenshots` 브랜치에 올리고 PR용 URL 출력 |

## 세션 규칙

- 세션을 시작하면 CONTEXT.md → STATUS.md를 읽고, STATUS.md의 "다음 작업"부터 이어 간다.
- 세션을 끝내거나 PR 상태가 바뀔 때마다 STATUS.md의 "세션 기록"과 "다음 작업"을 갱신한다. 다음 세션이 이 폴더만 읽고 이어 갈 수 있어야 한다.
