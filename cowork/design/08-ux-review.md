# 08. 사용자 관점 시안 검토 (v1.2)

검토: 디자인 세션 · 2026-10-27
대상: `site/*.html` v1.2, `system/*`
기준: [PRD-001](../prd/001_site_master-plan.md) 페르소나·여정(J1~J4), [04-design-system.md](./04-design-system.md)
방법: 로컬 서버로 렌더링해 1280×720, 360×640, 다크/라이트, ⌘K 팔레트를 직접 조작하며 확인

## 결론

**전체 방향은 좋고, 구현으로 넘어가도 된다.** 다만 05~07 리뷰가 "PRD 요구사항을 지켰는가"를 봤다면, 이번에는 "각 페르소나가 실제로 편하게 쓰는가"를 봤고, 그 기준에서 고칠 것이 9건 나왔다. 그중 **H1~H3은 구현 전에 시안에서 먼저 정리**하는 것을 권한다.

### 잘된 점 (유지)

- 홈 1280×720에서 히어로, featured, 칩, 첫 글까지 한 화면에 들어온다(F-HM-01).
- 글 상세 데스크톱: 21:9 썸네일을 없애고 시리즈 박스를 접어 둔 덕분에 첫 화면에서 바로 본문을 읽기 시작할 수 있다.
- 리스트 문법(meta → title → support)이 홈·프로젝트·관련 글·팔레트에서 같아서, 한 번 익히면 모든 페이지를 같은 방식으로 훑을 수 있다.
- About 모바일 첫 화면에 이름·직무·연차·회사·연락처 버튼이 모두 보인다(F-AB-01).
- 프로젝트 상세의 문제 → 접근 → 구조 → 결과 → 배운 점 흐름이 면접관이 읽기 좋은 순서다.
- 라이트/다크 전환, 팔레트 그룹(posts / projects), 키 힌트 정상.

### 참고 (조치 선택)

- **TOC 현재 위치 표시가 약하다.** 1px accent 선 + 글자 밝기 차이뿐이라 데스크톱에서도 한눈에 안 들어온다. v1.1의 "굵은 측면선 금지" 규칙은 유지하되, 현재 항목에 `font-weight 600`을 더하면 충분하다.
- **모바일 홈 첫 화면에 글이 없다.** 히어로 + featured 1개 + `projects →`가 첫 화면을 다 쓴다. "혼합형" 정체성 결정에 따른 것이라 그대로 둬도 되지만, 히어로 스택 토큰 줄(`kubernetes eks …`)을 모바일에서 숨기면 첫 글 제목이 약 60px 올라온다.
- 글 상세 제목이 영어(`Custom network Karpenter ENI troubleshooting`)이고 설명은 한국어다. 디자인 문제는 아니고 콘텐츠 정리(PRD P9 태그 정규화와 같은 시점) 대상.

3. 구현 단계에서 처리: L1, L2, 참고 항목
