EKS 네트워킹 아키텍처 고도화

Pod IP 고갈과 VPC CNI의 iptables 성능 한계를 Custom Networking과 Cilium CNI 체이닝으로 해결했습니다.

eksvpc-cniciliumebpfkarpenterterraform

문제

서비스가 늘수록 Pod에 줄 IP가 없었다.

기존 서브넷 대역만으로는 클러스터 전체에서 Pod에 줄 수 있는 IP가 약 500개였습니다. MSA 전환으로 서비스가 늘면서 배포 때마다 Failed to assign an IP가 발생했고, iptables 기반 VPC CNI는 서비스 수에 비례해 네트워크 처리 비용이 커졌습니다.

접근

IP 대역은 분리하고, 데이터 경로는 eBPF로.

  • VPC Secondary CIDR를 Pod 전용 서브넷으로 할당하고 EKS Custom Networking 구성
  • VPC CNI와 Cilium을 체이닝해 AWS 네이티브 라우팅은 유지하고 eBPF 기반 정책·관찰성을 추가
  • Karpenter Node가 ENI 1개를 점유하는 문제를 reservedENIs로 보정

구조

결과

500 → 16K
Pod IP 풀 (32배)
−30%
Pod 간 통신 레이턴시
−20%
노드 CPU 사용률
  • IP 풀은 VPC Secondary CIDR로 Pod 전용 대역을 분리해 늘렸고, 레이턴시·CPU는 Cilium CNI chaining의 eBPF 데이터 경로로 줄였다
  • Hubble UI로 네트워크 흐름 가시성 확보, Cilium Network Policy로 서비스 간 트래픽 제어

배운 점

관리형 노드와 Karpenter 노드는 같은 클러스터 안에서도 "알고 있는 정보"가 다릅니다. 네트워크 설정을 바꿀 때는 노드를 만드는 주체마다 같은 전제를 공유하는지 먼저 확인해야 한다는 것을 배웠습니다.
