## 3. 수정 요청

### 3.1 About 직함이 360px에서 3줄 (Q19 ②의 결과)

영문 직함 `DevOps · Cloud Native Engineer`는 한글 직함보다 폭이 넓다. 아바타 오른쪽 열이 228px뿐이라 직함이 두 줄로 쪼개지고 `· 경력 4년+`는 구분점이 줄 맨 앞에 떨어진다.

**수정안 A(권장):** 480px 미만에서 직함 줄을 아바타 행 아래로 내려 **전폭**으로 쓴다(아바타 + 이름은 한 행).
```css
@media (max-width: 479px) {
  .about-intro > div:first-of-type { display: contents; }   /* 이름·직함 래퍼를 풀어 격자에 직접 배치 */
  .about-intro__name { grid-column: 2; align-self: center; }
  .about-intro__role { grid-column: 1 / -1; }
}
```
(시험은 `about-intro`가 `72px 228px` 2열 격자인 현재 구현에 CSS만 얹어 쟀다.)

| 폭 | 지금 | A안 |
|---|---|---|
| 412 | 2줄, 버튼 335 / 소개 428px | 1줄, 369 / 462px |
| 360 | **3줄**, 359 / 450px | **1줄**, 369 / 460px |
| 320 | **3줄**, 358 / 477px | 2줄, 393 / 512px(구분점이 줄 맨 앞에 올 수 있음) |

- 320px 이하에서는 A안도 직함이 두 줄이 되어 구분점이 줄 맨 앞에 올 수 있다(줄 수만 쟀고 모양은 보지 않았다). **340px 이하에서만** 직함과 경력을 줄 단위로 나누고 구분점을 숨긴다: `@media (max-width: 340px) { .about-intro__role > span { display: block } .about-intro__role > span[aria-hidden] { display: none } }`.
- 어느 폭에서도 첫 화면 안에 이름·직함·연차·버튼이 보이고 가로 넘침 0이다(360×640 소개 하단 460px).
- 화면(360×640, 구현 `out/` 그대로 / A안 CSS를 얹은 것): [지금](../review/36-about-360-now.png), [A안](../review/36-about-360-fixA.png).

### 3.2 About 인쇄가 6쪽 (Q19 ⑤, PR-22)

**원인:** 구현 `globals.css`의 `@media print` 블록(818줄)에 시안과 같은 값이 다 있는데, **같은 선택자의 일반 규칙이 그 뒤쪽에 있어 소스 순서에서 이긴다.** 인쇄 미디어로 계산한 값으로 확인했다.

| 속성(print 미디어) | 의도(블록 값) | 실제 적용 값 |
|---|---|---|
| `.about-intro` display | `block` | `grid` |
| `.about-section` margin-top | 12pt = 16px | **64px** |
| `.about-intro__headline` font-size | 12pt = 16px | 20.18px |
| `.proj__points li` line-height | 1.45 | 19px(1.6) |
| `.skills > div` columns | 90pt | 160px 520px |
| `.stack-token` display | `inline`(쉼표 글자) | `flex`(칩 테두리 그대로) |

**검증:** 같은 `@media print` 블록을 `<head>` 맨 뒤에 한 번 더 붙여 인쇄하면 A4 폭 문서 길이 5,737px(5.62쪽 분량) → **4,139px(4.06쪽 분량)**, PDF **5쪽·543KB**로 시안(4,112px, 5쪽)과 같아진다. 위 표의 값도 모두 의도대로 바뀐다. 즉 **6쪽은 내용(Okta·Temporal 수정, skills 2개)이 늘어서가 아니라 규칙 순서 때문이다.**

**요청:**
- `@media print` 블록을 `globals.css` **맨 끝**(About 규칙 뒤)으로 옮기거나, 선택자를 `@media print` 안에서 한 단계 더 구체적으로 쓴다. `resume.pdf`뿐 아니라 사용자가 직접 `⌘P`로 인쇄할 때도 같은 문제다.
- 완료 기준: 인쇄 미디어에서 위 표의 의도 값이 계산되는지 E2E로 한두 개 확인(예: `.about-section` margin-top 16px, `.stack-token` display `inline`), A4 PDF **5쪽·1MB 이하**, 프로젝트가 쪽 경계에서 갈리지 않음.
- 쪽 수가 5쪽이 되면 작성자가 실제 Chrome ⌘P로 한 번 더 확인해 주세요.

### 3.3 홈 첫 글 위치 +49px (Q21 ①)

원인은 개발이 짚은 대로다. 시안은 `main`에 위쪽 여백이 없고 히어로가 자체 위쪽 여백(데스크톱 56px, 모바일 32px)을 갖는 반면, 구현은 `main`이 `py-12`(48px)를 이미 주고 있어 히어로 여백이 더해진다(히어로 시작 y=113 = 헤더 65 + main 48).

**권장:** `main`의 `py-12`는 모든 페이지가 쓰는 사이트 공통 여백이므로 두고, **홈 히어로의 위쪽 여백을 0으로** 한다(`.hero { padding-top: 0 }` — `home.css`의 `.hero` 두 줄). 그러면 홈도 다른 페이지처럼 헤더 아래 48px에서 시작한다.

| | 시안 | 지금 | 히어로 위 여백 0 |
|---|---|---|---|
| 1280×720 첫 글 제목 하단 | 458 | 505(+47) | **449(−9)** |
| 360×640 첫 글 제목 하단 | 437 | 485(+48) | **453(+16)** |

두 화면 모두 화면 안이고 시안과의 차이가 ±16px 이내다. `main` 여백 자체를 줄이는 안은 글 상세·About 등 다른 화면의 위쪽 여백을 모두 바꾸므로 권하지 않는다.

### 3.4 About 상단 경로(`~/about`) 복원

시안 `about.html`은 상단에 `~ / about` 경로(`path`)가 있고, `DESIGN.md` 시그니처 2번("path `~/posts/slug`: 모든 페이지 상단")과 글 상세(`post/PostPath`)도 그렇다. **구현 About에는 경로가 없다**(Q19에 적히지 않은 차이). 1280px에서 버튼 하단이 시안(301px)보다 32px 올라온 것(269px)이 이 경로 한 줄의 높이다.

- 요청: `post/PostPath`를 재사용해 About 상단에 `~ / about`을 둔다(`aria-label="현재 위치"`, 마지막 항목 `aria-current="page"`). **인쇄에서는 숨긴다**(`no-print`, 시안과 같음).
- 홈에는 경로가 없다(히어로가 그 역할). 404·그 밖의 화면은 이번 범위 밖.
- 복원하면 1280×720에서 버튼 하단이 시안과 비슷한 301px 근처가 된다(3.1 수정 후 360px은 약 369px).

## 4. 승인한 것의 근거

- **영문 직함(Q19 ②):** PRD-004 4.2의 `role`이 영문이고 같은 데이터가 JSON-LD `jobTitle`·experience 회사 직함 줄에도 쓰인다(한 곳에서 관리). 한글 직함은 10번 D4(Phase 0)의 결정이지만 PRD가 데이터 원본이 된 뒤 영문으로 정해졌으므로 따른다. CONTEXT의 직함 결정을 영문으로 고쳤다. 줄바꿈 문제는 3.1로 푼다.
- **한 줄 소개의 `최한수입니다`:** 이름이 바로 위 h1에 있어 중복 같지만, 원본 About 문장이고 "문장은 바꾸지 않고 옮긴다"가 PRD 원칙이다. 5초 테스트에는 영향 없다. 시안과 달라 360px에서 두 줄이 되는 것은 허용 범위(소개 하단 460px).
- **`BoB 10기`:** 원본(`about/page.tsx` 구버전)이 `BoB 10기`였다. 시안이 `(Best of the Best)`를 풀어 쓴 것이라 구현이 원본에 맞다. 시안을 고치지는 않는다.
- **팔레트 `esc 닫기`(Q20 ①):** 보이는 글자 `esc`를 이름에 포함하고(`aria-label="esc 닫기"`), 터치 영역이 46×42px로 44px에 2px 모자라지만 가로가 넓어 실사용 문제는 없다. **선택 개선:** 터치 기기에는 Esc 키가 없으므로 640px 미만에서는 보이는 글자를 `닫기`로 바꾸면 더 분명하다(이름 `닫기`, 보이는 글자와 같아 규칙 충족). 필수 아님.
- **태그 버튼(Q21 ②):** `aria-haspopup="dialog"` 버튼, 높이 44px. 클릭하면 팔레트가 그 태그로 열려(입력란 `eks`, 결과 8개) Esc로 닫으면 포커스가 그 버튼으로 돌아온다. 태그 페이지(Phase 3)가 생기면 링크(`tag.html` 시안)로 되돌린다.
