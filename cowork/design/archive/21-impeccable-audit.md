# 21. Impeccable audit: 컴포넌트부터 페이지까지

작성: 디자인 세션 · 2026-10-31
대상: 개발 세션(요청은 개발 `REQUESTS.md` Q14), 사용자

## 방법과 한계 (먼저 읽을 것)

- **번들 감지기(`impeccable detect`)를 실행하지 못했다.** 이 스킬의 완전한 사본은 `scripts/impeccable` 런처가 GitHub release에서 **네이티브 바이너리를 내려받아 실행**하는 구조라서, 사용자 확인 없이 실행하지 않았다. 지침이 정한 대체 경로(`PRODUCT.md`·`DESIGN.md`를 직접 읽고 `audit` 플레이북 수행)로 진행했다. 5번 차원은 수동 검토다.
- 전역에 설치된 impeccable은 `SKILL.md`만 있고 `scripts/`·`reference/`가 없는 **불완전한 사본**이었다. 완전한 사본(63개 파일)을 임시 폴더에 받아 `reference/audit.md`를 읽었다.
- 도구: axe-core(wcag2a/aa·2.1·2.2 aa·best-practice)를 **다크·라이트 × 360·1280 × 7페이지**(홈, About, 404, 글 4편)에 실행. 포커스·터치 대상·재배치·토큰 대비는 Playwright로 직접 계산했다.
- **성능은 이번에 Lighthouse를 다시 돌리지 않았다.** 번들 크기·이미지·모션은 새로 쟀고, 점수·LCP·TBT는 개발 `REQUESTS.md` Q12~Q13의 기록을 인용했다(기획이 성능 기준을 시뮬레이션이 아니라 **관측 측정**으로 바꿨다: 관측 LCP 홈 1.9s·글 2.0s·About 2.0s, About TBT 344~376ms, 시뮬레이션 76~83점은 정정된 값). 처음 이 보고서는 지난 시뮬레이션 수치(0.68~0.83, LCP 3.9~6.9s)를 근거로 성능을 2점으로 매겼으나, 최신 합의 기준에 맞춰 3점으로 고쳤다.

## 발견 사항

### P1

**[P1] 가로 스크롤되는 코드 블록이 키보드로 닿지 않는다**

| | |
|---|---|
| 위치 | `.code > pre` (본문 코드 블록 전체. `install-cilium-eks` 글의 `<pre>` 5개 중 `tabindex`가 있는 것이 0개) |
| 범주 | 접근성 |
| 영향 | 키보드·스위치 사용자가 긴 줄을 가로로 스크롤할 방법이 없다. axe `scrollable-region-focusable`(serious)이 글 3편에서 코드 블록 10개를 잡았다. 360px에서 가장 많고, 1280px에서도 넓은 yaml·hcl 블록이 걸린다 |
| 기준 | WCAG 2.1.1 Keyboard (A) |
| 권장 | `<pre>`에 `tabindex="0"`, `role="region"`, `aria-label`(예: `yaml 코드`)을 주고 포커스 링을 기존 accent로 보이게 한다. 복사 버튼은 그대로 |
| 명령 | `$impeccable harden` |

### P2

**[P2] 글자를 200%로 키우면 헤더와 PC 목차가 넘친다**

| | |
|---|---|
| 위치 | 헤더 `nav`(360px + 글자 200%에서 가로 +209px), PC 목차 `aside`(`src/app/posts/[id]/page.tsx:103`, 1280px + 글자 200%에서 +216px) |
| 범주 | 반응형 |
| 영향 | 확대해서 읽는 사용자가 가로 스크롤을 해야 한다. 글 4편·홈·About·404 모두 헤더에서 같은 값 |
| 기준 | WCAG 1.4.4, 1.4.10 |
| 권장 | 헤더 링크를 줄바꿈하거나 좁은 폭에서 접는다. PC 목차는 큰 글자에서 숨기거나 본문 아래로 내린다. 320px(기본 글자)에서는 모든 페이지가 통과한다 |
| 명령 | `$impeccable adapt` |

**[P2] 터치 대상이 작다**

360px에서 잰 크기. 시안의 원칙(`CONTEXT.md` 5장)은 "가능하면 44px"이고 WCAG 2.5.8 AA는 24px이다.

| 대상 | 크기 | 비고 |
|---|---|---|
| 로고 `~/comstering_` | 105×20 | 높이 24 미만 |
| 헤더 링크(posts, about) | 42×20 | 높이 24 미만. `Header.tsx`에 히트 영역 확장이 없다. 링크 사이 간격이 있어 간격 예외로 통과할 수 있으나 계산하지 않았다 |
| 헤딩 앵커 `#` | 10×23 | 호버 때만 보이는 보조 링크 |
| 카테고리 칩 | 약 30 | 시안은 32px + `::after`로 히트 영역을 위아래 6px 넓힌다. **`Chip.tsx`에는 `after:` 확장이 없다** |
| 테마 토글 | 36×36 | |
| 코드 복사 | 약 32 | |

- 참고: 브레드크럼 `~` 링크는 `after:-inset-x-2`로 히트 영역을 넓혀 두었다(요소 박스 8×44, 실제 약 24×44). 같은 방식을 칩·헤더 링크에 쓰면 된다.
- 영향: 모바일 정확도. 범주: 반응형. 명령: `$impeccable adapt`.


### P3

| # | 내용 | 위치 | 명령 |
|---|---|---|---|
| 1 | PC 목차 `aside`가 다른 랜드마크 안에 있다(axe `landmark-complementary-is-top-level`). 안에 이미 `nav aria-label="목차"`가 있으므로 `aside`를 `div`로 바꾸거나 본문 밖으로 | `src/app/posts/[id]/page.tsx:103`, 1280px 글 4편 | `$impeccable harden` |
| 2 | 본문 외부 링크 43개가 `rel="nofollow"`만 있고 `noopener`가 없다. 현대 브라우저는 `target="_blank"`에 `noopener`를 자동 적용하므로 위험은 낮다. 명시적으로 `noopener noreferrer`를 더하는 것을 권한다. `nofollow`를 모든 외부 링크에 쓰는 것은 작성자 정책 결정 | 마크다운 외부 링크 처리(`rehype-external-links`) | `$impeccable harden` |

About의 긴 작업(TBT 344~376ms)은 기획 Q13이 `content-visibility` 등으로 이미 다루고 있다. 좋은 점: 이미지 75개 중 `alt` 누락 0, `width`·`height` 누락 0, 63개 `lazy`. `will-change`·`filter`·`transition: all` 0건 | 홈 566KB·글 481KB, `out/_next/static` | `$impeccable optimize` |
| 4 | 칩 줄 오른쪽 가장자리의 페이드 마스크 때문에 axe가 칩 글자 대비를 "수동 확인"으로 남겼다(4곳). 화면에서는 문제없어 보이나 판정은 못 했다 | 홈 `PostsBlock` 칩 줄 | `$impeccable polish` |

## 확인된 좋은 점 (유지할 것)

- **테마:** 다크 `fg/canvas 16.19`, `mute/canvas 6.53`. 라이트 `fg/canvas 17.01`, `mute/canvas 5.19`, `accent/canvas 4.99`. 모든 글자 쌍이 AA 이상이다. 라이트는 `accent`가 4.99로 기준(4.5)에 가깝다. 토글 클릭 시 값이 바뀌고 저장되며 새로고침 후 유지된다. **저장값이 라이트일 때 JS를 2초 지연시켜도 첫 화면이 라이트**여서 깜빡임이 없다. 저장값이 없으면 시스템 설정과 무관하게 다크로 시작하는데, 이는 디자인 명세(04번 "다크 기본")와 일치한다.
- **모션:** 애니메이션은 확대 보기 하나뿐이고 `prefers-reduced-motion: no-preference`일 때만 켜진다. 전역 모션 끄기 같은 거친 처리가 없다.
- **구현 위생:** `!important` 0, 인라인 `style` 0, `div`에 `onClick` 0, `globals.css` 컴포넌트 클래스 27개 중 쓰이지 않는 것 0, 빌드 CSS 검사(`check:output`)가 글꼴 단축 속성 깨짐을 막는다(Q8).
- **포커스:** 키보드 Tab 순회에서 모든 요소에 포커스 표시가 있다. 목록·관련 글은 행 전체에 accent 링이 그려진다(`:has()` 패턴). 처음 "포커스 없음 14건"으로 잡혔으나 제 검사가 링크 자신을 부모 행으로 잘못 읽은 **거짓 양성**이었다.
- 새 창 링크 중 `target="_blank"` 48개는 `noopener noreferrer`를 갖고 있다.

## 권장 조치 (우선순위순)

1. **[P1] `$impeccable harden`** — 코드 `<pre>`에 `tabindex="0"`·`role="region"`·`aria-label`, PC 목차 `aside` 랜드마크, 외부 링크 `rel`.
2. **[P2] `$impeccable adapt`** — 글자 200%에서 헤더·PC 목차 넘침, 터치 대상 44px(헤더 링크·로고·칩 히트 영역. 브레드크럼 `~`의 `after:` 방식을 따른다).
3. **[P3] `$impeccable optimize`** — JS·렌더링 차단 CSS 줄이기. About은 기획 Q13의 진행 결과를 먼저 본다.
4. **[P3] `$impeccable polish`** — 칩 줄 페이드 대비, 마무리.

## 개발에 요청 (Q12)

위 1·2번(P1, P2 두 건)을 개발 `REQUESTS.md`에 **Q14**로 보냈다. P1은 한 줄(`tabindex="0"`)에 가까운 수정이다. 3번은 기획 Q13이 진행 중이라 요청하지 않았다.

## 확인하지 못한 것

- 번들 감지기(`impeccable detect`) 실행. 5번 차원의 결정적 검사.
- 라이트 테마 화면은 홈 360px, 글 상세 1280px만 눈으로 봤다. 나머지는 수치와 axe.

- 실제 Chrome(Claude in Chrome은 Remote Control에서 불가), Safari·Firefox, 실기기, 스크린리더 실제 낭독.
- Lighthouse 재측정(성능 수치는 개발 Q12~Q13 기록 인용).
- WCAG 2.5.8 간격 예외 계산.
