_기간 2026-10-27 ~ 2026-11-01 · 디자인 v1.0 → v1.4 · 기준 기획서 PRD-001·003 · 개발 PR #27 ~ #57 검토 · 보관 2026-11-01_

디자인 세션의 Phase 1 기록에서 **핵심만** 모은 보관본이다. Phase 0(01~11번)의 정리는 [phase0-summary.md](./phase0-summary.md)에 따로 있다. 원문 중 12·19·21번만 이 폴더에 남아 있고 나머지는 삭제했다. 번호별 위치와 Git 복구 방법은 [README.md](./README.md). 시안 `../site/`와 명세 `../04-design-system.md`는 그대로다. 새 세션은 이 문서를 읽지 않아도 된다(시작은 `../CONTEXT.md` → `../STATUS.md`).

## 1. 결과

- 디자인 시스템 **v1.4 확정**. 시안 9종(home, post, projects, project, about, tags, tag, 404, og)과 `design-system.html`, 공용 `system/`(토큰·컴포넌트 CSS·JS).
- 확정된 값은 저장소 `/DESIGN.md`에 반영돼 있고 코드가 따른다(`yarn check:tokens`가 `src/`를 검사).
- 구현된 화면을 시안과 대조한 검토 5회(17·19·20·21번과 2026-11-01 Chrome 확인). 시안과 어긋난 구현 결함은 모두 개발에 요청해 반영됐다. 단 마지막 요청(Q14, #57)의 반영분은 **재확인하지 못했다**.
- Phase 1 종료. 포트폴리오(Phase 2, PRD-004)의 디자인 요청은 18번에 있다.

## 5. 겪은 함정 (디자인 쪽)

- **dev 서버로는 안 보이는 문제가 있다.** 빌드 압축 후에만 깨지는 CSS가 있었다(`font:` 단축 속성). 구현 검토는 항상 `yarn build`한 `out/`으로 한다.
- **측정 방식이 숫자의 의미를 바꾼다.** 처음 성능을 시뮬레이션 수치로 2점 줬다가 기획이 관측 측정으로 바꾼 것을 확인하고 3점으로 정정했다. 점수는 기획의 측정 기준을 먼저 확인하고 매긴다.
- **자동 검사의 거짓 양성.** 포커스 "없음 14건"은 내 검사 방식의 오류였다. 이상치는 눈으로 한 번 더 본다.
- **Playwright가 놓친 것을 실제 Chrome이 잡는다.** 확대 창 배경 스크롤은 Playwright 확인에서 "정상"으로 적었던 항목이다. "확인했다"에는 도구를 같이 적는다.
- 자동 검사(axe)는 페이드 마스크 아래 글자 대비를 "수동 확인"으로 남긴다(홈 칩 줄 4곳). 눈으로는 문제없어 보이나 판정은 못 했다.
- 시안의 `.ph` 표시는 `src/`에서 검사에 걸린다. 시안 단계에만 쓴다.
- 문서 번호는 재사용하지 않는다(10번은 08번과 겹쳐 옮긴 결과).

## 6. 일하는 방식에서 굳어진 것

- 세션 시작 때 `CONTEXT.md` → `STATUS.md`를 읽고, 작업이 끝나기 전에 기록을 먼저 고친다.
- 질문·답은 `NN-주제.md`로 쓰고 `README.md` 표에 한 줄 넣는다. 개발 `REQUESTS.md`에는 번호만 링크한다.
- 디자인은 `/DESIGN.md`와 `src/`를 고치지 않는다. 합의된 것만 구현 세션이 반영한다.
- 확인하지 못한 것은 "못 했다"고 적고, 측정값에는 환경(브라우저·빌드 기준)을 같이 적는다.
