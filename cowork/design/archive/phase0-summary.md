## 3. 핵심 결정과 근거

**디자인 방향·원칙**
- Terminal Graphite를 뒤엎지 않고 넓힌다. 시그니처 5개(cursor, path, comment label, mono meta, arrow)와 리스트 문법(meta → title → support)을 모든 화면에 적용.
- 신규 토큰: `line-strong`(조작 요소 경계, 3:1 이상), `warn`(경고 콜아웃·오류에만 쓰는 예외 색), `accent-soft`, `overlay` 등. 그림자는 쓰지 않는다.
- 규칙: 본문 강조에 accent를 쓰지 않는다(링크처럼 보인다, 08 M3), 장식용 점·em dash·섹션 번호 금지, 터치 44px.

**기획 검토 R1~R10 중 의미가 큰 것 (05~07)**
- 수치·문구의 **사실성**: 성격이 다른 두 절감액을 합친 `$66K/yr` 지표 삭제(실측 하나만), 근거 없는 "IP 부족 장애 0건" 삭제, 시안용 값은 `.ph`로 표시하고 구현에서는 데이터로만 채운다.
- 모바일 터치 영역: 행 링크의 앵커 자체를 44px 이상으로(시각 크기는 그대로). 태그는 32px + 간격 12px로 WCAG 2.5.8 충족.
- Giscus는 iframe이라 직접 그린 UI 대신 `giscus-dark/light.css`로 토큰 색만 맞춘다.
- 글 상세 첫 화면에서 시리즈 박스는 기본 접힘(글이 주인공).

**사용자 관점 검토 H1~L2 (08, v1.3)**
- **H1** 모바일 글 첫 화면에 본문 0줄 → 목차·시리즈를 한 줄 두 버튼으로 합침(360×640 첫 h2 652 → 542px). 이 기준이 나중에 개발 게이트 G1-4가 됐다.
- **H2** About ↔ Projects 항목 불일치 → 누락 4건을 추가해 14건으로 맞추고 About 링크가 각 프로젝트 행으로 가게 함.
- **H3** 같은 글이 세 번 나오던 것 → 관련 글에서 같은 시리즈·이전/다음 글을 제외, 남는 글이 없으면 섹션 숨김(억지로 채우지 않음).
- M1~M4: 근거 글 앵커를 헤더 메타 줄에, About 직무·연차를 이름 아래 본문 크기로, `연속성` accent 강조를 굵기로, 경력 행에 `→`. L1~L2: 결과 불릿 중복 제거, 가로 스크롤 표 오른쪽 흐림.

**사용자 결정 (10번, v1.4 요청 D1~D6)**
- 카테고리 `infra / backend / frontend / oss / note`(`web` 통합 안 함), AdSense는 지금은 제거, 새 사내 정보를 추가할 때만 작성자 확인.
- 프로젝트 "근거 글"은 **"관련 글"**로 바꾸고 개인 EKS 글은 `personal` 표기. 회사 프로젝트 다이어그램에는 개인 환경 값을 쓰지 않는다.
- 직함 `DevOps · Cloud Native Engineer`(Class101은 `Web Developer (backend 중심)`).
- 원칙 4에 "회사 성과와 개인 실습 글을 섞어 보이지 않는다" 추가.

## 4. 겪은 함정·배운 것

- 시안은 PRD를 **지켰는지**와 사용자가 **편한지**가 다른 검사다. 05~07은 앞의 것, 08은 뒤의 것으로 서로 다른 문제(H1~H3)를 찾았다.
- 시안에 만든 수치·문장은 면접에서 검증 질문에 걸린다. 표시(`.ph`)하지 않으면 사실로 보인다.
- 문서 번호가 세션끼리 겹칠 수 있다(기획이 쓴 08번이 10번으로 이동). 번호는 재사용하지 않는다.
- 남의 이미지(AWS 공식 다이어그램)는 톤이 부딪혀도 그대로 둔다. 직접 그리는 다이어그램만 토큰 SVG로.
