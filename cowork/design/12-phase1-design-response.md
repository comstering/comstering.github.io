## 결론

1. **categories는 B안(대표 없음, 고정 순서로 전부 표시)을 추천한다.** 두 값을 쉼표로 묶어 한 덩어리로 보여 준다: `infra, oss`.
2. **목록 썸네일은 OG 축소본으로 바꾸지 말고 목록에서 빼는 것을 추천한다.** 09에서 제가 A안(OG를 목록에도)을 추천했지만, 14편을 실제로 렌더링해 보니 판단이 틀렸다. 아래 3장에 이유를 적었다. OG 자동 생성(PR-15)은 그대로 진행한다.
3. PRD-003 작업에 필요한 시안(확대 보기, 카테고리 2개 표시, OG 하단 줄, 목차 없는 글의 도구 줄)과 미뤄 둔 v1.4 요청(D1~D5)을 반영했다.

### 2번 상세: 원칙 2 "포인트 색 하나"와 맞는 쪽

- 원칙 2는 **색이 한 종류**라는 뜻이고, accent의 용도는 "링크·활성·포커스·CTA"다(08 M3에서 정한 규칙). 헤더의 category는 둘 다 필터로 가는 **링크**이므로 둘 다 accent인 것이 규칙과 맞는다.
- A안은 두 번째 category를 mute로 만드는데, 그것도 링크다. **눌러지는데 링크처럼 안 보이는** 상태가 되어 08 M4(About 경력 줄)에서 고친 문제가 다시 생긴다. 반대로 mute를 링크가 아닌 텍스트로 만들면 같은 값이 어디서는 링크, 어디서는 텍스트가 된다.
- 강조가 둘로 갈리는 걱정은 **쉼표로 묶어** 한 덩어리로 보이게 하면 해결된다. 쉼표는 mute 색, 링크에서 뺀다.

### 1번 보충: 메타 줄 규칙

- 줄이 넘치면 항목 단위로 다음 줄로 내려간다(`flex-wrap`, 항목 안에서는 줄바꿈 없음). 글자 중간에서 끊기지 않으므로 넘쳐도 괜찮다.
- 다만 최악 조합이 320px 중 312px이라 여유가 8px뿐이다. **시리즈 `label`(목록용 짧은 이름)은 8자 이하로** 정해 두면 앞으로도 한 줄이 유지된다. 지금 값 `eks`, `cilium`은 문제없다. → PRD-003 PR-12 또는 `content/series.yaml` 검증에 추가 요청

### 칩 숫자 (PRD-003 6장 리스크)

**칩 숫자는 그대로 둔다.** 합이 전체보다 커도(`infra 11 + oss 2 + frontend 2 + note 1 = 16`, all 14) 혼란이 적다. 칩 숫자는 "이 칩을 누르면 몇 편이 나오는가"를 알려 주는 용도이고, 실제로 눌렀을 때 그 수만큼 나온다(시안에서 5개 칩 모두 일치 확인). 숫자를 빼면 0편 숨김 규칙과 함께 쓸 근거도 약해진다.

## 3. 목록 썸네일: 09 A안 철회, 목록에서 빼기를 추천

`phase1-compare.html` 마지막 섹션에 지금(수동 로고) / OG 축소본 / 썸네일 없음을 같은 행으로 나란히 놓았다.

| | 지금 (수동 로고) | OG 축소본 (현재 결정) | 썸네일 없음 (추천) |
|---|---|---|---|
| 보이는 것 | 기술 로고. 톤이 제각각 | 7px 크기의 제목. **읽을 수 없고, 바로 옆 제목과 같은 내용** | 없음 |
| 시선 | 썸네일이 가장 시끄러움(09 V1) | 조용하지만 정보가 0 | 제목에 바로 감 |
| 모바일 (640px 미만) | 원래 숨김 | 원래 숨김 | 같음 |
| 홈 이미지 요청 | 14개 | 14개 (각 ≤ 80KB 목표) | 0개 |

- OG 이미지는 1200×630에서 읽히도록 만든 것이라, 128×67로 줄이면 제목 글자가 약 7px가 된다. 그 결과 목록 썸네일은 **바로 옆 제목을 읽을 수 없는 크기로 한 번 더 쓴 것**이 된다. 톤 문제(V1)는 풀리지만 썸네일이 있어야 할 이유가 없어진다.
- 주 독자인 모바일 검색 유입(J2)은 지금도 목록 썸네일을 보지 않는다(640px 미만 숨김). 썸네일을 빼도 J2의 경험은 그대로다.
- 데스크톱 홈에서 이미지 14개가 빠지면 G1-2(성능 ≥ 95) 여유가 생긴다.
- 6장 리스크 "어떤 기술인지 한눈에"는 썸네일이 아니라 메타 줄(category·시리즈)과 태그가 이미 맡고 있다.

**기획에 요청하는 변경:**

| PRD-003 | 지금 | 제안 |
|---|---|---|
| G1-6 | 모든 글에 고유 OG 이미지 + 홈 목록 썸네일도 같은 이미지 | 모든 글에 고유 OG 이미지. 홈 목록에는 썸네일을 두지 않는다 |
| G1-5 | 썸네일 ≤ 80KB | 삭제(본문 이미지 ≤ 200KB만) |
| PR-15 목록 썸네일 | OG 축소본(640×336 WebP)으로 교체 | `PostListItem`에서 썸네일 제거. frontmatter `thumbnail`은 선택 필드로 남기되 아무 곳에도 쓰지 않으면 PR-9에서 스키마에서 삭제 검토 |

결정은 기획·작성자가 한다. 받아들여지면 `index.html`·`tag.html` 썸네일을 빼고 `post-item`의 썸네일 열을 정리하겠다.

## 4. PRD-003 다른 항목에 대한 의견

| # | 위치 | 의견 |
|---|---|---|
| E1 | PR-9 URL 연동 | **규칙과 수용 기준이 서로 맞지 않는다.** URL 갱신을 `router.replace`로 하면 방문 기록이 쌓이지 않아서, 수용 기준 2 "칩 전환 후 뒤로가기로 이전 필터 복원"이 되지 않는다. 시안은 `pushState`(Next.js의 `router.push(url, { scroll: false })`)로 만들었다. 추천: **push로 바꾼다.** replace를 유지하려면 수용 기준 2를 뺀다 |
| E2 | PR-11 코드 복사 | 시안의 bash 블록은 `$ ` 프롬프트를 쓴다. "복사 내용은 원문 그대로"면 프롬프트까지 복사되어 붙여 넣으면 실행이 안 된다. 추천: `bash`·`sh`·`shell` 블록은 줄 맨 앞 `$ `를 빼고 복사한다(화면에는 남김). 글 원문에 `$ `가 없는 지금 글들은 영향 없음 |
| E3 | PR-14 확대 | 화면에 이미 원본 크기로 보이는 이미지(작은 스크린샷 등)는 눌러도 커지지 않는다. **원본 폭 > 표시 폭인 이미지에만** 확대를 붙이고, 아니면 `cursor: zoom-in`과 버튼 역할을 주지 않는다. 빌드 타임에 `width`를 이미 알게 되므로(PR-14 2번) rehype 단계에서 판단 가능 |
| E4 | PR-15 OG 디자인 | PRD에 "아래 accent 선"이 있는데 `og.html` 시안에는 없다. **선은 넣지 않는 것을 추천.** 로고 커서 `_`가 이미 accent 한 점이고, 선을 더하면 공유 카드에서 강조가 두 곳이 된다 |
| E5 | PR-15 형식 | og:image는 **PNG를 유지**(시안 PoC 기준 24~55KB라 용량 문제 없음). 일부 공유 미리보기(메신저류)는 WebP를 읽지 못한다 |
| E6 | PR-15 글꼴 | PoC에서 Pretendard 700 + JetBrains Mono 400으로 렌더했다. satori에도 이 두 굵기만 넣으면 된다 |
| E7 | PR-12 | 1280 이상에서 h2가 3개 미만이라 sticky 목차를 숨길 때, 본문은 **가운데로 옮기지 않고** 같은 자리에 둔다. 글마다 본문 시작 위치가 달라지지 않게 하기 위해서 |
| E8 | PR-12 시리즈 label | 1장 "1번 보충"대로 `label` 8자 이하 검증 추가 |
| E9 | G1-4 | 시안 기준 360×640 첫 h2 542px, 첫 문단 612px로 통과. 제목이 3줄을 넘는 글은 이 값이 줄 수만큼 내려가므로 E2E는 가장 긴 제목의 글로 측정한다 |
