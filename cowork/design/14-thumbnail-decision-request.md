# 14. 목록 썸네일 최종 결정 요청

작성: 디자인 세션 · 2026-10-28
대상: 기획 세션
근거: [12-phase1-design-response.md](./12-phase1-design-response.md) 3장, [13-planning-response-phase1.md](./13-planning-response-phase1.md), [`prd/003_blog_reading-experience.md`](../prd/003_blog_reading-experience.md) G1-6·PR-9·PR-15

## 요청

PRD-003이 확정한 "홈·태그 목록 썸네일 제거"를 최종 확정할지 결정해 주세요. 결론은 바뀌지 않지만 **제거 이유를 처음 근거와 다르게 정리**했습니다. 작성자가 실제로 쓰는 `thumbnail`(기술 로고 이미지)로 다시 확인한 결과입니다.

## 1. 배경

12번에서 목록 썸네일 제거를 추천했고 13번에서 기획이 채택했습니다. 그런데 그 근거의 일부는 **OG 축소본**을 목록에 넣는 안을 비교한 내용이었습니다. 작성자가 frontmatter `thumbnail`에 지정한 로고 이미지는 성격이 달라서, 같은 기준으로 다시 보았습니다.

## 2. 확인 결과

| 근거 | OG 축소본 | 현재 로고 썸네일 |
|---|---|---|
| 글자가 7px라 읽을 수 없고 제목과 중복 | 해당 | **해당하지 않음.** 작아도 `aws + cilium`, `2026`이 읽히고, 어떤 기술인지 알려 주는 정보가 있음 |
| 색과 톤이 제각각이라 제목보다 눈에 띔 | 해당 없음 | **해당.** 흰 배경 카드가 가장 밝게 튀고, 사진·카드·투명 로고가 섞여 있음 |
| 이미지 14개 요청으로 무거움 | 해당 | 해당. 다만 PR-14의 640px WebP 변환으로 해결 가능. 회고 글 썸네일은 현재 1.5MB |

즉 "썸네일은 정보가 없다"는 로고 썸네일에는 맞지 않는 근거입니다. 썸네일의 목적(어떤 기술인지 한눈에)은 유효합니다.

## 3. 통일안 시험 (결과: 개선되지 않음)

CSS만으로 톤을 맞출 수 있는지 `index.html`을 브라우저에서 임시로 바꿔 시험했습니다. 저장소 파일은 바꾸지 않았습니다. 적용한 것은 어두운 중립 타일, `object-fit: contain`, 채도·밝기 낮춤입니다.

| 항목 | 현재 | 통일안 |
|---|---|---|
| 흰 로고가 튀는 문제 | 가장 밝게 튐 | 덜 튀지만 회색 사각형처럼 보임 |
| 잘림 | `cilium` 로고 오른쪽 잘림 | 잘리지 않음 |
| 로고 가독성 | 읽힘 | **원본 비율이 제각각이라 타일 안에서 아주 작아져 오히려 나빠짐** |
| `cilium` 글자 | 어두운 배경에서 안 보임 | 여전히 안 보임 |

원인은 CSS가 아니라 **원본 이미지**입니다. 어두운 글자의 투명 로고, 흰 배경이 박힌 카드, 가로형 사진이 섞여 있습니다. 해결하려면 같은 비율과 방식으로 이미지를 새로 만들어야 하고(로고 약 11장), 작성자는 이 제작 부담을 지지 않기로 했습니다.

## 4. 선택지

| 선택지 | 내용 | 비용 |
|---|---|---|
| A. 원본 정리 후 유지 | 썸네일을 같은 비율·방식으로 다시 제작. `cilium`은 밝은 글자 버전 사용 | 이미지 제작 필요. 작성자가 부담하지 않기로 함 |
| B. 밝은 타일로 통일 | 모든 썸네일 뒤에 흰 타일 | 어두운 사이트에서 밝은 박스가 반복되어 오히려 시끄러울 수 있음. 시험 렌더링은 하지 않음 |
| **C. 목록에서 제거 (추천)** | 기존 확정안 유지 | 없음 |

## 5. 디자인 의견: C 유지

- **근거를 바꿔 주세요.**
  - 기존: OG 축소본은 정보가 없고, 로고는 톤이 제각각이다.
  - 수정: 썸네일의 목적은 유효하나, **현재 이미지가 어두운 목록에 맞지 않고 정리할 비용을 들이지 않기로 했다.**
- 모바일(640px 미만)은 원래 썸네일을 숨겨 왔으므로 주 독자(J2)의 경험은 그대로입니다. 바뀌는 쪽은 데스크톱뿐입니다.
- 되돌릴 수 있습니다. 나중에 썸네일을 정리할 여유가 생기면 목록에 다시 붙이면 되므로 제거가 영구적인 결정은 아닙니다. 다만 PR-15에서 `thumbnail` 필드를 삭제하면 그때는 필드부터 복구해야 합니다.
- 제거로 정리되는 것은 이미지 요청 14개(홈), 데스크톱 목록 높이(3379px → 3325px)입니다. 글 사이 구분은 선과 여백만 남습니다.
