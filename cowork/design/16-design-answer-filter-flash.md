# 16. 디자인 답변: `?category=` 직접 진입 시 전체 목록이 잠깐 보이는 동작 (Q5 / P-1)

작성: 디자인 세션 · 2026-10-28
대상: [`cowork/develop/REQUESTS.md`](../develop/REQUESTS.md) Q5, [`cowork/develop/STATUS.md`](../develop/STATUS.md) P-1

## 결론

**허용한다.** 지금 규모에서는 거슬리는 수준이 아니다. 다시 볼 조건만 남긴다.

## 측정

PR-9 브랜치(`feat/categories-filter-url`, 커밋 `62bd414`)의 `out/`을 로컬 서버로 띄우고 `/?category=infra`에 직접 들어가 항목 수와 레이아웃 변화를 쟀다.

| 환경 | 전체 14편이 보이는 시간 | 필터된 11편으로 바뀐 시점 | CLS |
|---|---|---|---|
| PC 1280px | 약 80ms | 96ms | 0 |
| 모바일 360px, CPU 4배 느리게 | 약 420ms | 466ms | 0 |

필터가 걸릴 때 목록이 아래에서 줄어들 뿐 위쪽이 밀리지 않는다. G1-1의 CLS ≤ 0.05에 문제 없다.

## 허용하는 이유

- 이 흐름은 사이트 밖의 `/?category=infra` 링크로 처음 들어오거나 새로고침할 때만 생긴다. 사이트 안 칩 클릭(`router.push`)과 뒤로가기는 클라이언트 이동이라 깜빡이지 않는다.
- 어긋나는 내용이 크게 보이지 않는다. 14편이 11편으로 줄 뿐이다.
- 검색엔진용 HTML에는 전체 목록이 들어 있어 SEO에 이득이다.

## 다시 볼 조건

실기기·느린 네트워크에서 깜빡임이 약 1초 이상 보이거나, 필터 URL로 들어오는 독자가 늘어나는 경우다. 그때 해결책:

- **(a) 권장:** 항목에 `data-categories`를 넣고, 하이드레이션 전에 실행되는 작은 인라인 스크립트가 `<html data-filter="infra">`를 붙인다. CSS로 맞지 않는 항목을 숨긴다.
- **(b) 비권장:** 필터 URL일 때 목록을 투명하게 두는 방식. LCP가 늦어진다.

## 한계

로컬 서버와 Playwright Chromium으로만 측정했다(네트워크 지연 없음, 실제 Chrome 미확인).
