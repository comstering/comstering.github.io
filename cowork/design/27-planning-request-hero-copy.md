## 배경

작성자가 25번 시안을 보고 **2b(터미널 명령 + 아래 일반 문구 한 줄)** 방향을 골랐다. 명령어는 하나로 정하지 않고 `git log`와 `history` 두 가지를 비교한다. 문구는 "직접 실행해 보고 남긴 기록", "직접 실행해 보고 한 줄씩 남기는 기록"이 좋지만 **임팩트가 조금 부족하다**는 의견이라, 더 짧고 힘 있는 후보를 함께 비교한다. 참고로 작성자가 좋게 본 예는 "기억보단 기록을"(다른 블로그)이다. 짧고, 맞세우고, 리듬이 있는 문장이다. 기억·기록 단어를 꼭 쓸 필요는 없다.

## 요청

| # | 우선 | 내용 |
| --- | --- | --- |
| D-11 | 필수 | **2b 히어로를 명령어 2종 × 문구 여러 개로 비교할 수 있게** `index.html` 비교 도구를 확장한다. 명령어 전환(`git` / `history`)과 문구 전환을 따로 고를 수 있게(주소 예: `?hero=2b&cmd=git&copy=g1`). 각 명령어에 어울리는 문구는 아래 표 |

### 명령어

| cmd | 표시 | 뜻 |
| --- | --- | --- |
| `git` | `$ git log --oneline` + 커서 `_` | 정리해서 남긴 기록. 한 줄씩 최신순이라 아래 글 목록 모양과 같다 |
| `history` | `$ history` + 커서 `_` | 직접 쳐 본 명령의 기록. 개발자가 아니어도 "기록"으로 읽힌다. 짧다 |

### 문구 후보 (아래 줄, `mute`)

**git용**

| id | 문구 | 비고 |
| --- | --- | --- |
| g1 | 직접 실행해 보고 한 줄씩 남기는 기록 | 작성자가 좋게 본 문구. `--oneline`과 이어짐 |
| g2 | **실행하고, 실패하고, 커밋한다** | 기획 추천. 세 박자 리듬, 삽질까지 남긴다는 태도 |
| g3 | **삽질도 커밋하면 이력이 된다** | 기획 추천. "이력"이 git history와 경력 두 뜻 |
| g4 | 잘된 것도, 안된 것도 커밋 | 짧고 솔직함 |
| g5 | 배운 만큼 커밋한다 | 가장 짧음 |

**history용**

## 확인해 줄 것

- 문구 길이별로 360px에서 한 줄에 들어가는지, 두 줄이 되면 줄바꿈 위치가 어색하지 않은지(가장 긴 g1·c1 기준).
- 첫 화면에 첫 글 제목이 보이는지(1280×720, 360×640). 25번 2b 수치(458px / 437px)와 비교.
- `history`는 명령이 짧아 위 줄이 가벼워 보일 수 있다. 위 줄 크기·굵기를 두 명령어에서 같게 둘지, `history`에 맞춰 조정할지 디자인 의견.
- 접근성: 25번처럼 터미널 줄 `aria-hidden`, h1 `sr-only` `Comstering's Dev Notes`. 문구 줄은 낭독되게(h1 다음 `p`).
- 디자인 의견으로 명령어 1개 + 문구 상위 3개를 추천해 주면 작성자가 최종 선택한다.
