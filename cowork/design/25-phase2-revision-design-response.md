## 2. D-8 About

### 2.1 구조 (PRD 5.1)

첫 화면 → 소개 → experience(회사 바로가기 + 21건) → open source · side → skills → certifications → education · activity. 22번에서 바뀐 점:

| 항목 | 22번 | 지금 |
|---|---|---|
| 경력 | 프로젝트별 접이식, `expand all` | **전부 펼침**, `<details>`·버튼 없음 |
| what i do | 있음 | **삭제** |
| 관련 글 | 항목 맨 아래, `personal` 배지 | **삭제** (About 안 `/posts/` 링크 0개, 측정함) |
| 자격증 | `verify ↗` (+후기 글 후보) | `verify ↗`만 |
| 오픈소스 | `merged` + PR 링크 + `관련 글` | `merged` + `pull request ↗` |
| 앵커 | 프로젝트 21개 | **회사 바로가기 3개**(`#cj-oliveyoung`, `#class101`, `#open-source`) |
| 첫 화면 | 버튼 4개 | 같음: `email`(primary) · `resume.pdf`(다운로드) · `github ↗` · `linkedin ↗` |

첫 화면 측정(Playwright Chromium): 360×640에서 버튼이 369px, 한 줄 소개가 460px에서 끝나고, 1280×720은 323px / 437px. 22번과 같다(소개 문단 구성이 바뀌지 않았다).

### 2.2 회사 바로가기

- experience 제목 바로 아래 한 줄: `CJ 올리브영` · `클래스101` · `오픈소스`. 44px 높이의 외곽선 링크(`line-strong`, hover `accent`)이고 줄이 모자라면 줄바꿈한다. 눌러서 간 곳은 `scroll-padding-top`(헤더 + 24px)이 맡는다. 측정: 세 링크 모두 도착 위치 88px(360·1280).
- **앵커 도착 강조는 없앤다.** 22번의 `surface-2` 강조는 항목 하나를 가리켰지만 이제 도착지는 회사 전체(프로젝트 7~14건)라 배경을 칠하면 화면 전체가 덮이고 무엇을 가리키는지 오히려 흐려진다. 회사 이름이 헤더 바로 아래에서 시작하는 것으로 충분하다(24번 D-8 ②: "필요하면 유지"에 해당하지 않는다고 판단).
- 프로젝트 `id`는 앵커가 아니라 데이터 키다. 마크업에는 남겨 두었다(링크로 쓰지 않는다).
- **개발 주의(22번 Q9):** `html { scroll-padding-top }`이 이미 있으므로 `scroll-margin-top`을 따로 주지 않는다.

### 2.3 길이 줄이기 (D-8 ⑦): 숫자로 정했다

21건을 모두 펼치면 길다. 레버별로 같은 문서에 CSS만 바꿔 쟀다(About 전체 높이, px).

| 변형 | 360px | 768px | 1280px |
|---|---|---|---|
| V0 22번 밀도 (줄간격 1.7, 불릿 간격 8, 프로젝트 간격 24) | 12,515 | 8,942 | 8,997 |
| V1 줄간격 1.6, 불릿 간격 4, 프로젝트 간격 16 | 11,610 | 8,166 | 8,221 |
| V2 = V1 + **기간 열 제거**(본문 전폭) | 11,610 | 7,375 | 7,430 |
| **V3 = V2 + 프로젝트 간격 12, 불릿 들여쓰기 12 (채택)** | **11,426 (−9%)** | **7,215 (−19%)** | **7,270 (−19%)** |
| V4 = V3 + 본문 14px | 10,618 (−15%) | | |

- 데스크톱의 큰 이득은 **기간 열을 없앤 것**이다(왼쪽 140px 열이 본문을 좁혀 줄바꿈이 많았다). 기간은 회사 이름 위 한 줄로 올린다. 프로젝트 기간은 제목 줄 오른쪽에 그대로.
- **360px은 글 양이 길이를 정한다.** 줄간격·간격을 줄여도 −9%에 그친다. 더 줄이려면 본문 글자를 14px로 내려야 하는데(−15%) DESIGN.md의 `text-small`(15px)을 벗어나고 한글 읽기에 불리해 **권하지 않는다.** 내용을 줄이는 방법은 기획이 축약 없음으로 정했다. 그래서 모바일은 회사 바로가기가 길이 문제를 덜어 주는 장치다.
- 글자 크기·색·굵기는 그대로다(프로젝트 제목 15px/600, 설명 `mute`, 불릿 `fg`).
- 마크업은 프로젝트마다 `article.proj`(`h4` 제목, 회사는 `h3`, 섹션은 `h2`라 제목 단계를 건너뛰지 않는다).

## 3. D-9 About 인쇄 (= `resume.pdf`)

22번 `resume.html`과 이력서 전용 CSS는 **삭제했다.** About 하나가 화면과 인쇄를 모두 맡는다.

| 규칙 | 내용 |
|---|---|
| 용지 | `@page` A4, 여백 13/14mm, 본문 9.5pt(프로젝트 9pt) |
| 색 | 인쇄 미디어에서 라이트 토큰으로 덮어쓴다. **다크 테마로 열어도 흰 배경·검은 글자** |
| 숨김 | 사진, 헤더, 푸터, 경로, 첫 화면 버튼 4개, 회사 바로가기, `now` 배지 |
| 연락처 | 버튼이 사라지므로 **인쇄 전용 한 줄**을 이름 아래 둔다: 이메일 · github.com/comstering · linkedin.com/in/… (화면에서는 숨김) |
| 링크 | 외부 링크 뒤에 `(URL)`을 붙인다(오픈소스 PR, Lomeone, Credly 검증). 화살표 아이콘은 URL 문구로 바뀐다 |
| 쪽 경계 | 프로젝트 하나, 오픈소스·자격증 행, 섹션 제목은 쪽 경계에서 갈라지지 않게(`break-inside`, `break-after: avoid`) |
| 기술 스택 | 화면의 칩 모양을 쉼표로 이은 글자로 바꾼다(종이에서는 테두리가 잡음) |

**결과** (Chromium `page.pdf()`와 인쇄 미디어 렌더):
- A4 **5쪽**, 632KB. 헤더·푸터·사진·버튼·바로가기 숨김, 배경 `#fff`·글자 `#111`, 외부 링크 URL 표시를 확인했다.
- 처음 렌더에서 **링크 URL이 점무늬로 깨지고**(아이콘 마스크가 남음), 자격증 `verify` 줄이 어긋나고, `merged` 표시가 같이 숨겨지는 문제가 나와 고쳤다(`merged`는 작은 글자로 남김).
- **Chrome 인쇄 미리보기 화면은 직접 열지 못했다.** 도구로 인쇄 대화상자를 열 수 없어서, 같은 엔진(Chromium)의 `page.pdf()`와 인쇄 미디어 렌더로 대신 확인했다.
- PDF 안 텍스트 검색·한글 글꼴 포함(G2-6)은 이 환경에서 PDF 텍스트를 읽을 도구가 없어 **확인하지 못했다.** PR-22에서 확인한다.

## 4. D-10 헤더 검색

시안(`.palette`)을 그대로 쓰되 24번 ①~⑤를 맞췄다. 모든 시안(`site/*.html`)의 헤더·팔레트에 반영했다(보관 화면 포함).

| 항목 | 결정 |
|---|---|
| 검색 대상 | **글만**(draft 제외). 제목·설명·태그·카테고리·소제목(h2·h3). 입력란 문구 "글, 프로젝트, 태그…" → **"제목, 태그, 소제목으로 글 검색"** |
| 결과 | 한 줄: 제목 · 날짜 · 카테고리. 제목 일치 → 설명·태그·카테고리 → 소제목 순 가중, 같으면 최신 글 먼저. 대소문자 무시, 부분 일치 |
| **소제목 일치 표시(제안)** | 소제목에서만 맞은 글은 제목 아래에 `# 소제목`을 작게 보인다(왜 이 글이 나왔는지 알려 준다). 필요 없으면 지워도 구조가 같다 |
| 빈 입력 | **최근 글 5편**(그룹 라벨 `recent`) |
| 결과 없음 | "‘…’에 대한 글이 없습니다. 제목, 태그, 소제목으로 찾습니다…" + 낭독기에 "검색 결과 없음" |
| 모바일 | 헤더에서는 **아이콘만**(36px, 터치 영역 46px), 팔레트는 전체 화면. 결과의 날짜·카테고리는 제목 아래 줄로 내려 보인다(처음에는 모바일에서 숨겼다가 요구 사항(날짜·카테고리)에 어긋나 고침) |
| 접근 가능한 이름 | `aria-label="검색 (search)"` + `aria-keyshortcuts="Meta+K Control+K"`. 24번은 이름 `검색`을 요청했지만, 데스크톱에서 보이는 글자 `search`가 이름에 들어 있어야 한다는 규칙(19번: 이름은 보이는 글자를 포함)과 맞추려고 **`검색 (search)`**로 했다. 모바일(아이콘만)에서도 같은 이름이라 `검색`으로 시작한다 |
| 낭독 | 결과 수를 `role="status"`로 알린다("글 3개", "최근 글 5편"), 결과 없음이면 `aria-expanded="false"` |
| 인덱스 | **처음 열 때 불러온다**(시안은 `search-index.js`를 그때 삽입, 구현은 dynamic import + `/search-index.json`) |

**키보드 점검**(Playwright, 홈): `⌘K` 열림, 입력란에 포커스, `/`로도 열림, ↓↓로 선택 이동, Enter로 글 이동, Esc로 닫힘(열기 전 포커스 위치로 복귀. 단축키로 열었으면 본문), `terraform` 검색 후 Enter가 글로 감. 홈·About·글 3개 화면에서 `⌘K`가 같이 동작한다. 실제 Chrome에서 `⌘K` → `eni` 입력 결과(제목 + 소제목 일치 줄 + 날짜·카테고리)를 확인했다.

시안의 인덱스는 실제 글 14편(draft 제외)에서 만든 것이라 결과가 구현과 같아야 한다. 예: `karpenter` → 3편(제목 2, 태그로 1), `ENI` → 3편(소제목 일치 포함).

## 5. D-6 홈 히어로 3안

한 파일에서 전환한다. **오른쪽 아래 `시안 비교 도구`**(기본 접힘, 구현 아님)에서 안과 대체 문구를 눌러 바꿔 볼 수 있고, 주소로도 열린다.

| 안 | 주소 | 구성 |
|---|---|---|
| 1 | `index.html?hero=1` | 한 줄 소개 문구만 (`배운 것과 만든 것, 그 사이의 기록`) |
| 2 | `?hero=2` | 터미널 문구만 (`$ git log --oneline` + 깜빡이는 커서) |
| **2b** | `?hero=2b` | 2안 + 아래에 `mute` 일반 문구 한 줄(24번이 요청한 변형) |
| 3 | `?hero=3` | `Comstering's Dev Notes` + 일반 문구 |

세 안 모두 실명·직함·기술 태그·성과·`about me`/`resume` 버튼·대표 프로젝트가 없다. 히어로 아래 순서는 카테고리 칩 → 연도별 글 목록(글 검색창 없음).

**공통 확인**(첫 글 제목 아래끝 y, 낮을수록 위):

| 안 | 1280×720 | 360×640 |
|---|---|---|
| 1 | 418px | 438px |
| 2 | 413px | 392px |
| 2b | 458px | 437px |
| 3 | 463px | 483px |

모두 화면 높이 안이다. 가로 넘침 0, h1 1개.

- **안 2의 접근성:** 보이는 터미널 줄은 `aria-hidden`으로 두고 h1 안에 `sr-only`로 `Comstering's Dev Notes`를 넣었다. 화면 낭독기는 사이트 이름을 읽고(`$ git log --oneline_`을 읽지 않는다), 검색 결과·탭 제목의 이름과 일치한다. 이 처리는 2·2b에 필요하다.
- **커서 깜빡임:** 사이트에서 이 한 곳. `prefers-reduced-motion: reduce`이면 정지함을 확인했다(`animation: none`).

### 디자인 의견: 2b를 권한다

| 안 | 장점 | 약점 |
|---|---|---|
| 1 | 가장 평범하고 안전 | 헤더 로고 `~/comstering_`와 겹치는 인상이 없고 개성이 약하다 |
| 2 | 브랜드(Terminal Graphite)와 가장 잘 맞음 | 명령만으로는 "무슨 블로그인지"가 약하다 |
| **2b** | 터미널 분위기 + 일반 문장으로 정체가 분명. `git log --oneline`은 아래 글 목록이 시간순이라는 사실과도 맞는다 | 두 줄이라 첫 글이 안 2보다 45px 내려감(그래도 첫 화면 안) |
| 3 | 사이트 이름이 크게 보임 | 헤더 로고와 이름이 중복되고 지금 라이브 홈과 가장 비슷하다 |

최종 선택은 작성자가 한다. 문구 후보는 24번 표를 그대로 비교 도구에 넣었다(일반 5, 터미널 4). 디자인 추천 문구는 24번과 같다(`배운 것과 만든 것, 그 사이의 기록`, `$ git log --oneline`).

## 6. D-7 홈 사이드바

| 블록 | 내용 | 비고 |
|---|---|---|
| popular | 순위 번호 1~5 + 제목(제목만, 44px 이상 행) | **시안의 5편은 샘플**이다(실제 순위는 GoatCounter 데이터가 정함) |
| series | 편수 + slug + 시리즈 제목 | `content/series.yaml` 2개 그대로 |
| tags | 글 수 상위 10개 + 글 수(작은 숫자) | 실제 글의 태그를 센 결과. 글 수 표시는 제안 |

- 카테고리·최근글·About 링크는 넣지 않았다.
- **1024 이상:** 오른쪽 열(sticky). **1024 미만:** **글 목록 아래**로 내려 위쪽 border로 구분한다(24번이 디자인 결정으로 넘김). 근거: 위에 두면 첫 글이 밀린다. 다만 목록이 길어 모바일에서는 사이드바가 페이지 끝에 있어 **거의 보이지 않는 위치**다(360px에서 사이드바 시작이 4,423px 중 약 3,500px). 질문 Q2.
- **인기글 없는 상태:** 블록이 숨겨지고 시리즈가 맨 위로 올라온다(위쪽 불필요한 간격 없음, 확인함). 비교 도구의 `인기글 데이터 없음 상태` 버튼으로 본다.
