# 02. 개선 방향성

PRD의 목표(5분 안에 "무엇을 해봤고 어떻게 생각하는가" 파악)를 화면으로 옮기기 위한 디자인 방향. DESIGN.md를 **뒤엎지 않고 넓힌다.**

## 1. 방향 한 줄

> **Terminal Graphite는 그대로, "읽는 블로그"에서 "증명하는 포트폴리오"로.**
> 모든 화면이 다음 한 걸음(근거 글, 프로젝트, 연락처)을 바로 보여준다.

## 2. 원칙 (DESIGN.md 4원칙 + 추가 3개)

DESIGN.md의 기존 원칙은 유지한다: ① 글이 주인공 ② 포인트 색 하나 ③ 토큰만 ④ 본문 Pretendard·메타 모노.

추가 제안:

5. **증명의 연결선을 보이게.** 성과 수치 옆에는 항상 근거 링크(`→ 글 보기`, `→ 프로젝트`)를 둔다. 페르소나별 여정(J1~J4)의 다음 단계가 스크롤 없이 또는 글 끝에서 바로 보여야 한다.
6. **한 화면, 한 목적.** 홈 = 훑어보기, 글 = 읽고 따라하기, About = 5초 요약, Projects = 성과 증명. 화면마다 주 행동(Primary)은 하나.
7. **리스트 문법 하나로 통일.** 글·프로젝트·관련 글·태그·검색 결과가 모두 같은 "메타(모노) → 제목 → 보조 설명" 구조를 쓴다. 한 번 익히면 모든 페이지를 같은 방식으로 읽을 수 있다.

## 3. 토큰 확장 제안

### 3.1 색 (추가)

| 토큰 | 용도 | 라이트 | 다크 | 근거 |
|---|---|---|---|---|
| `line-strong` | 입력창·칩·버튼 등 **조작 요소의 경계** | `#7D8E86` | `#5A6D65` | `line`은 1.3:1이라 WCAG 1.4.11(3:1) 미달. 제안값 대비: 라이트 3.17(canvas)·3.45(surface), 다크 3.49·3.29·3.11(surface-2). 구분선은 계속 `line` |
| `warn` | WARNING 콜아웃, 주의 표시 **전용** | `#8A5A00` | `#F2C14E` | F-PO-12. 대비 5.93 / 10.8. 포인트 색 원칙의 유일한 예외로 범위를 한정 |
| `overlay` | 명령 팔레트·라이트박스 뒤 딤 | `rgb(12 15 14 / .72)` | `rgb(0 0 0 / .72)` | 그림자 없이 레이어를 구분 |
| `code-hl` | 코드 줄 하이라이트 배경 | `rgb(91 242 155 / .08)` | 동일 | F-PO-04. 왼쪽 2px `accent` 선과 함께 |

원칙: `accent`는 계속 하나. `warn`은 콜아웃과 상태 표시 외에 쓰지 않는다. 성공 상태(복사 완료, merged)는 새 색 없이 `accent`를 쓴다.

### 3.2 타이포 스케일 (역할에 고정)

| 역할 | 데스크톱 | 모바일(<640) | 폰트·굵기 |
|---|---|---|---|
| hero headline | 48 / 1.2 | 32 / 1.25 | Pretendard 700, -0.04em |
| post title (h1) | 40 / 1.3 | 30 / 1.3 | Pretendard 700, -0.03em |
| 본문 h2 | 26 / 1.4, 위 여백 56 | 22 | Pretendard 700 |
| 본문 h3 | 20 / 1.5, 위 여백 40 | 18 | Pretendard 600 |
| list title | 22 / 1.35 | 20 | Pretendard 600 |
| **body (prose)** | **17 / 1.8** | 16 / 1.8 | Pretendard 400 |
| meta, nav, label | 13 | 13 | JetBrains Mono 400, 소문자 |
| caption, tag | 12 | 12 | JetBrains Mono |
| code | 0.85em, line-height 1.7 | 동일 | JetBrains Mono |

- 본문 17px: 720px 폭에서 한 줄 약 40자. 긴 한글 기술 글을 읽기에 가장 편한 구간(35–45자)이다.
- 숫자(성과·기간·날짜)는 `font-variant-numeric: tabular-nums`로 정렬한다.
- 한글 줄바꿈은 `word-break: keep-all`을 기본으로 한다(현재 일부만 `break-keep`).

### 3.3 레이아웃·간격

| 항목 | 값 |
|---|---|
| 브레이크포인트 | `sm 640` 모바일↔태블릿, `md 768` About 2단, `xl 1280` TOC 사이드 |
| 헤더 높이 | 64px → `--header-h` 토큰화. 앵커 `scroll-margin-top: calc(var(--header-h) + 24px)` (F-PO-03 수용 기준) |
| 글 상세 그리드(≥1280) | 컨테이너 1120 = 여백 200 · 본문 720 · TOC 200. 본문은 가운데 고정 |
| 터치 영역 | 모든 클릭 요소 최소 44×44px. 시각 크기는 유지하고 패딩이나 `::before`로 히트 영역만 키운다 |
| 레이어 | `z-header 40`, `z-progress 41`, `z-overlay 50`, `z-modal 60` |

## 4. 화면별 방향

우선순위는 PRD Phase 0을 따른다: **글 상세 → 헤더·푸터 → 홈 히어로 → About → Projects → 팔레트·태그·404**.

### 4.1 글로벌 셸 (F-GL-01~03)

- **헤더:** `~/comstering_` · `posts` `projects` `about` · 검색 · 테마.
  - 360px에서는 로고가 `~/_`로 줄어들어 한 줄을 유지한다([01 §5](./01-baseline-audit.md) 계산).
  - 검색 버튼은 데스크톱에서 `search ⌘K` 텍스트를 보여주고, 모바일에서는 아이콘만 보여준다.
  - 현재 위치는 `text-fg`와 함께 밑줄 2px `accent`로 표시한다. 색만으로 구분하지 않기 위해서다.
- **읽기 진행률(F-PO-10):** 헤더 하단 2px `accent`. 글 상세에서만 표시한다.
- **푸터:** 왼쪽 `© 2026 comstering`, 오른쪽 `github · linkedin · email · rss` (모노, `mute` → hover `accent`).

### 4.2 글 상세 (F-PO-01~12) — 최우선

```
[≥1280px]
            ┌──────────── 720 ────────────┐  ┌── 200 ──┐
            infra · 2025-07-06                on this page
            Karpenter로 유연한 Node…  (40px)    ─ 개요
            설명 한 줄 (mute, 18px)              ─ 설치      ← 현재: fg + 왼쪽 accent 선
            8 min read · 1,204 views · upd …     ─ 트러블슈팅
            ─────────────────────────────
            ┌ series: eks-from-scratch 3/4 ┐
            │ 1 EKS 구축                  │
            │ 2 Custom Networking         │
            │ 3 Karpenter   ← 지금 글     │
            └─────────────────────────────┘
            본문 …
            ┌ values.yaml ─────── yaml ⧉ ┐
            │ code …                      │
            └─────────────────────────────┘
            ── 저자 박스 ── 이전/다음 ── 관련 글 3 ── 댓글
```

- **헤더(F-PO-01):** 21:9 대형 썸네일을 없애 첫 화면에 본문이 바로 보이게 한다. 썸네일은 OG·목록용으로만 쓴다(`cover: true`일 때만 예외).
- **목차(F-PO-03):** `on this page` 라벨(모노 12). 항목 13px `mute`, 현재 항목은 `fg` + 왼쪽 2px `accent`. h3은 들여쓰기 12px. 1280 미만에서는 본문 위에 접이식 `<details>`로 두고, 기본은 닫힘이다.
- **코드 블록(F-PO-04):**
  - 상단 36px 바: 왼쪽에 파일명(모노 12, `code-fg` 70%), 오른쪽에 언어 라벨과 복사 버튼.
  - 복사 후 아이콘이 ✓로 바뀌고 `copied`(accent)가 2초간 표시된다. `aria-live="polite"`로 알린다.
  - 하이라이트 줄은 `code-hl` 배경 + 왼쪽 2px `accent`.
  - 모바일은 블록을 화면 끝까지 붙이고(좌우 -20px) 모서리를 0으로 한다. 가로 스크롤 공간을 넓히기 위해서다.
- **콜아웃(F-PO-12):** `surface` 배경 + 왼쪽 3px 선 + 모노 라벨(`note`/`warning`). NOTE = `accent`, WARNING = `warn`. 아이콘은 쓰지 않는다.
- **시리즈 박스(F-PO-07):** `surface` + `line` + `md` 모서리. 번호는 모노, 현재 편은 `fg 600`과 `← 지금 글` 표시. 5편 초과 시 접는다.
- **글 끝 순서:** 저자 박스(F-PO-09) → 이전/다음(F-PO-05, 2단·모바일 1단, 라벨 `← prev` `next →`) → 관련 글 3편(F-PO-06, `PostListItem` compact: 썸네일 없음, 설명 1줄) → (광고, 결정 시) → 댓글(F-PO-08).
  - 저자 박스에 `about →` `projects →` 링크를 두어 J3 여정과 KPI "글 → About/Projects 이동률 ≥5%"를 직접 받친다.
- **이미지(F-PO-11):** `md` 모서리, `line` 테두리, 캡션은 `mute` 14px 가운데 정렬. 라이트박스는 `overlay` + Esc/클릭으로 닫힌다.

### 4.3 홈 (F-HM-01~04)

```
~/comstering — cloud native engineer              (모노 13, mute)
개발과 운영의 경계를 좁히는                         (48px)
클라우드 네이티브 엔지니어
kubernetes · eks · karpenter · cilium · terraform  (모노 13)
[about →]  [projects]                              (primary / ghost)

featured ─────────────────────────────────────
2025 · MWAA 제거, Airflow on EKS 이전       연 $16,000 절감
2024 · Pod IP 고갈 해결 (Custom Networking)  500 → 16,000
2024 · …

[search ⌘K]  all 15 · infra 6 · k8s 4 · …         (칩 + 글 수)
2025 ───────
글 목록 …
```

- **1280×720에서 첫 글 제목이 보여야 한다(F-HM-01).** 히어로는 약 260px 이내로 잡는다. featured 3줄(F-HM-02)이 들어가면 넘칠 수 있으므로 두 가지 안을 시안으로 비교한다.
  - A안: featured를 목록 아래로 내린다.
  - B안: featured를 히어로 오른쪽 열(≥1024)에 둔다.
- **검색:** F-SR-01 팔레트가 나오면 큰 검색창을 칩 줄 왼쪽의 `search ⌘K` 트리거로 바꾼다. 세로 공간을 약 70px 아낄 수 있다.
- **칩(F-HM-04):** 글 수를 함께 표시하고(`infra 6`), 선택 상태를 URL에 반영한다. 높이 32px을 유지하되 히트 영역은 44px로 늘린다.

### 4.4 About (F-AB-01~04) — 5초 테스트 통과가 목표

- **첫 화면(스크롤 없이):** 아바타 96 · 이름 · 직무 · 연차(`7y` 같은 모노 배지) · 핵심 역량 3줄 · 연락처 버튼.
  - 핵심 역량 각 줄 끝에 근거 링크(`→`)를 둔다(원칙 5).
  - 연락처: `email`(primary) · `github` · `linkedin` · `resume.pdf ↓`.
  - ≥768에서는 2단(왼쪽 프로필, 오른쪽 역량), 모바일에서는 1단.
- **경력 타임라인(F-AB-02):** 회사별 그룹. 왼쪽 모노 기간 열(120px) + 오른쪽 내용. 프로젝트는 제목 + 한 줄만 보여주고 `→` Projects 상세로 보낸다. 세로 연결선은 `line` 1px.
- **자격증(F-AB-03):** 리스트로 보여주고 오른쪽에 `verify ↗`(Credly)를 둔다.
- 현재 카드·그림자·`sky-500` 구조는 폐기하고 다시 만든다.

### 4.5 Projects (F-PJ-01~04, 신규)

목록 항목:
```
2024.03 – 2025.02 · company                       (모노 13, mute)
Airflow MWAA → EKS 이전                           (22px, 600)
연 $16,000 비용 절감                                (숫자만 모노·fg 600)
kubernetes  airflow  terraform                    (스택 칩, line-strong)
```
- 숫자 강조는 `accent`가 아니라 굵기와 모노로 한다. 포인트 색을 아끼기 위해서다.
- 스택 필터는 홈 칩과 같은 컴포넌트를 쓴다.
- **상세(F-PJ-03):** 섹션 라벨을 `01 problem` `02 approach` `03 architecture` `04 result` `05 lessons`(모노)로 단다.
  - 결과 수치 2–3개는 카드가 아닌 **위아래 선으로 구분한 한 줄**에 32px 모노로 보여준다.
  - 아키텍처 다이어그램은 토큰 색 SVG로 그린다(선 `line-strong`, 강조 노드 `accent`).
  - 마지막에 "관련 글" 리스트를 둔다.
- **오픈소스(F-PJ-04):** `repo · PR 제목 · merged`(merged = `accent` 모노 라벨).

### 4.6 명령 팔레트 (F-SR-01)

- 위치: 위에서 15vh, 폭 `min(640px, 100% - 32px)`, `surface` + `line-strong` 1px + `lg` 모서리, 뒤는 `overlay`. 그림자 금지 규칙은 유지한다.
- 입력창 56px. 결과는 `posts` `projects` `tags` 그룹(모노 라벨)으로 나눈다.
- 선택된 행은 `surface-2` + 왼쪽 2px `accent`. 하단에 키 힌트 `↑↓ 이동 · ↵ 열기 · esc 닫기`.
- 모바일에서는 전체 화면 시트로 띄운다(입력창이 상단에 붙음).

### 4.7 태그·404·OG

- **/tags:** 터미널 `ls` 느낌의 점선 리더 리스트(`kubernetes ······ 7`). 2단(≥640).
- **404:** `$ cd /요청경로` → `no such file or directory`(모노, `mute`) → 최신 글 3편 → `cd ~` 홈 링크. 커서 깜빡임은 쓰지 않는다(히어로 전용 규칙).
- **OG 1200×630(F-SE-02):** 다크 `canvas` 배경, 왼쪽 위 `~/comstering_`, 제목 Pretendard 64 Bold 최대 3줄, 하단 `date · category`(모노). 안전 여백 80px.

## 5. 결정 필요 사항 — 디자인 관점 의견

| 항목 (PRD 8.2) | 디자인 추천 | 이유 |

| MDX 도입 | **찬성** | 콜아웃·코드 파일명·다이어그램 컴포넌트를 본문에서 일관되게 쓰기 쉬움 |
